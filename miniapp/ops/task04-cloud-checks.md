## 并发、故障与权限

- owner 直接退出拒绝；普通成员不能移除/转移；跨家庭 UID 和不存在 UID 均不可访问；额外/伪造字段拒绝，成员只返回 uid/nickname/role/generation。
- 同一 owner 同时向 B/C 转移、转移与移除、转移与 B 退出竞争：按提交顺序只有一个有效结果，家庭始终恰有一个 owner，角色与 ownerUid 一致。
- 以相同成员槽作栅栏的受保护写分别先于/后于退出或移除提交；移除生效后旧上下文写不得落库。并发读取发生变化时必须重试或安全失败，不能返回旧成员列表。
- B 退出后使用未消费且有效的邀请重入，generation 必须改变。旧上下文、旧首次迟到操作、旧成功回执均不能作用于新槽。A→B→A 后原邀请不可消费。
- leave/remove 各四个业务写点、transfer 六个写点逐一失败，确认成员、家庭版本和回执没有部分提交。分别丢失 commit 确认，验证同 requestId 恢复；重用 requestId 换目标/代次必须冲突。
- 记录实际厂商冲突错误码及隔离语义，不能猜测错误码或以本地替身证明；未知错误安全失败。验证跨实例 UID/家庭限流、内部重试不重复计数。
- 五个业务集合的 clientDB read/create/update/delete 共二十项均拒绝；检查平台自动请求日志不保留凭据或用户原行。
- 故障/暂停探针如确有需要，须先提出独立临时资源清单并获得授权；不能向正常公开云对象加入 debug/run/fixture 方法。清理探针后重新绑定正常工件摘要。

## 真机

1. 普通成员取消退出不发送请求；确认退出后保持登录、回到家庭引导，历史家庭内容不随用户搬迁。
2. owner 移除另一设备成员；被移除者返回页面或发起下一请求时隐藏旧内容并回引导，旧 token 无法获取原家庭数据。
3. 转移后双方重进刷新角色；原 owner 可退出，新 owner 不能直接退出。目标显示稳定 UID，避免同名误操作。
4. 转移/退出成功但响应丢失，断网冷启动后用完整原请求恢复；重试不重新生成 requestId。查询失败只显示重试，不推断无家庭。
5. 确认框尚未结束时隐藏/卸载页面、退出登录或切换账号；迟到确认不发送请求，迟到响应不恢复旧数据或跨账号导航。

不做实时推送：云端立即撤销后续授权；客户端在 onShow 或下一次请求检测后更新。逐项记录设备、系统、微信基础库、场景结果与受测包摘要；未执行项保持 pending。所有必需场景以 `TASK04_SCENARIOS` 为准。
