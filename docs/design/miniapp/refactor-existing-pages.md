# 既有页面 UI 重构工单正文

已发布：[pray4her/mealie #20](https://github.com/pray4her/mealie/issues/20)，`ready-for-agent`，原生阻塞 0 项。此文件记录工单范围；GitHub 正文中的设计与代码引用使用固定提交链接。发布回读见 [工单约定](issue-design.md)。

## What to build

将已经交付的登录、家庭与菜谱页面，按用户已认可的“家常”设计基线重构为可读、可操作、适配手机的实际微信小程序界面。

用户可以通过微信登录/家庭引导进入菜谱，以明确的搜索与收藏入口查找菜谱，查看私有菜图、食材和步骤，并继续完成创建、共同编辑和已有家庭管理操作。操作成功、错误、权限失效和恢复提示保持真实。

## Design evidence

- 基线：`docs/design/miniapp/README.md` v1；视觉目标 `miniapp/design-preview/index.html`；来源及批准记录 `docs/design/miniapp/sources.md`。
- 采用 D-01/02/03/06/07/08/09：白色内容面、深绿操作、真实菜图、系统中文字体、Wot 控件、可访问性与真实状态。
- 业务规则：总体业务设计第 3、6、8、10.1、12、14 节；已经交付的 #1–#7。
- 代码基准：`0dc31abfff4cfd53df90ad5a8161ed7498c0eaa2` 的 `miniapp/`。Wot 尚未接入；页面以原生按钮/表单为主，复用既有 features 与契约。
- 预览适配：采用构图、色彩与层次；不采用假家庭数据、样例统计/评分、浏览器 DOM、简化编辑器、模拟导入、购物去重、固定日期或尚未交付功能入口。

## Scope and boundaries

- 页面：`pages/account/login`；`pages/family/onboarding`、`home`、`invite`、`join`、`members`；`pages/recipes/index`、`detail`、`edit`。
- 一并核对 `App.vue`、`uni.scss`、`pages.json`、所有受导航变更影响的调用方/守卫、共享文案、依赖锁文件及页面测试。
- 本票内验证当前 uni-app/Vue/Vite 与 Wot 的兼容性，锁定版本、Sass、easycom 和主题；随后迁移页面。保留 uni-id 必需模块，不升级与目标无关的框架，不修改第三方源码。
- 视觉集中到应用主题；通用交互使用 Wot，平台授权/路由/预览使用原生能力，业务逻辑复用已有 composable。只提取实际需要的共享业务组件。
- 导航只包含真实可用的菜谱与家庭入口；采用 TabBar 时同步路由调用方与登录/家庭守卫，不添加空白计划/清单页。
- 不修改云对象、数据库模型、权限、AI 配额或媒体策略；不迁移旧 Nuxt/Vuetify 页面，不引入生产假数据。
- #8 本地未提交工作及 #9–#19 不属于本票必需输入。AI、计划、购物、评论、评分等原工单后续按相应模式设计，不在本票提前实现。

## Acceptance criteria

- [ ] Wot 在项目当前编译链实际可用，版本/主题/easycom/Sass 有记录；完成微信构建，按钮主次和主题在页面及弹层中一致。
- [ ] 上述 9 个页面均有真实业务数据和原有操作；没有预览家庭、静态评分、伪统计、空白导航或未交付功能假按钮。
- [ ] 菜谱双列 `4:3` 图文、完整详情、结构化编辑和搜索/收藏/分页正常；窄屏及大字号必要时单列，未知数量/份数/时间不伪造或丢失。
- [ ] 私有图片的加载、无图、审核/失败、链接到期与预览按已有契约工作；不改为公开永久 URL，不为列表装饰绕过媒体授权。
- [ ] 微信登录、创建/加入/邀请、邀请续接、普通成员退出、所有者移除/转移、权限限制和确认提示均保持正确；导航与页面隐藏/切换不泄露旧家庭内容。
- [ ] 列出并验证正常、加载、空、失败、权限失效、未确认请求恢复、版本冲突、媒体失败状态；不适用项说明原因，业务错误不能只剩 Toast。
- [ ] 320/375/390/430 逻辑像素与大字号下无页面横向溢出、关键裁字、操作重叠；安全区、底部固定操作和软键盘不遮挡内容。
- [ ] 满足基线可访问性：重要交互至少 44×44、必要对比度与标签、非颜色唯一反馈、可识别异步状态；适用平台验证屏幕阅读和输入行为。
- [ ] 更新真实交互回归而非只改选择器；现有家庭/菜谱/私有媒体/恢复与并发测试继续通过，`task -d miniapp check` 全通过。
- [ ] 附实际微信渲染截图（页面、状态、屏宽、设备/工具版本）、与已认可 HTML 的差异和原因；fixture、开发者工具及真机证据分开记录，不能以 jsdom 自检代替真机或云验收。
