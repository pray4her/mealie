## 1. 意图、范围与成功标准

让已经微信登录、尚未加入家庭的用户填写家庭名称，创建自己的家庭，成为唯一所有者并进入家庭页。再次打开小程序时，云端确认其已有家庭后直接进入家庭页。

本票交付从数据结构、云端事务、页面交互到测试验收的完整行为。成功标准是同一用户只有一个有效成员槽，活跃家庭恰有一个有效所有者，重试不会多建家庭，并发失败或事务中断不会留下孤儿数据。按钮防连点仅改善交互，不承担唯一性约束。

只修改 `miniapp/` 和本票设计、计划文档；不修改旧 Nuxt/FastAPI、生成类型、根依赖和旧服务。不实现邀请、加入、改名、所有权转移、退出家庭或解散，这些仍归 #3/#4；不提前搭建其他业务页面、公开社区或默认共享家庭。不提供可由客户端任意指定 UID、家庭归属或角色的入口。

## 4. 数据与不变量

所有时间为服务端 UTC 毫秒，ID、角色、状态和版本由云端生成。成员记录只保存当前关系，未来离开时释放槽；历史内容不靠成员槽永久保存。

| 集合 | 本票字段 | 约束 |
| --- | --- | --- |
| `families` | `_id`, `name`, `ownerUid`, `status:'active'`, `version`, `createdAt`, `updatedAt` | 家庭 ID 随机生成；活跃家庭的 ownerUid 对应同家庭的有效 owner 成员槽 |
| `family_members` | `_id = uid`, `familyId`, `role`, `generation`, `mutationSeq`, `joinedAt`, `updatedAt` | 一个 UID 一个槽；创建时 role=owner，generation 为随机新值，mutationSeq=0 |
| `mutation_receipts` | 确定性 `_id`, `uid`, `operation`, `requestId`, `payloadHash`, `result`, `createdAt` | 主键由版本化编码的 UID、操作名、requestId 摘要派生，不使用歧义拼接；与家庭、成员原子提交 |
| `request_limits` | 确定性 `_id`, `subject`, `operation`, `windowStart`, `count`, `expiresAt` | 跨实例原子计数；拒绝的业务写不能回滚掉已经计入的调用 |

家庭创建不额外建立 ownerUid 全局唯一索引，以免阻碍未来用户离开后重新建家庭。成员槽主键保证 UID 唯一，业务服务保证 role 和 ownerUid 一致；不给任意角色编辑入口。家庭下成员检索采用普通 `familyId` 索引，不使用会误限制多个普通成员的 role 唯一索引。

四个集合的 Schema 对 clientDB `read/create/update/delete` 全部设为 false，包括回执和限流数据。传统云端数据库 API 不依赖 Schema 自动验证，必须显式做字段白名单、长度、状态、权限和结果校验。部署前核验主键与所需查询索引实际存在且生效；不假造平台不需要的重复主键索引文件。

本票不自动清理成功创建回执，避免无定义的重放期限。限流过期桶可复用或由受控维护清理；本票不公开清理方法，也不为此部署后台 worker。

## 5. 对外契约与权限

沿用总计划：

- `Mutation = { requestId: string }`。
- `FamilyContext = { uid, familyId, role:'owner'|'member', generation }`。
- 本票细化返回值为 `FamilyView = FamilyContext & { name: string }`。名称用于家庭页显示，避免为了显示名称新增第三个公开读取方法；`FamilyContext` 继续作为授权内部上下文，不携带账户隐私字段。
- `FamilyApi.current(): Promise<FamilyView|null>`。
- `FamilyApi.create(input: Mutation & { name: string }): Promise<FamilyView>`。

`current` 不接受目标家庭/用户参数。`create` 仅接受 requestId、name，额外字段拒绝。UID 从已验证身份得到；familyId、ownerUid、role、generation 不读取客户端同名字段。响应不带 openid、token 数组、审核细节或数据库原行。顶层 `newToken` 继续由现有统一调用边界处理。

每个入口复用 #1 的 `requireIdentity`，验证当前账户、实际 token 和允许的 App/平台。随后用可信 UID 读取成员槽和家庭。`current` 在同一只读事务快照中确认关系：无槽返回 null；有槽但家庭缺失、非活跃或角色/所有者关系不一致时安全失败，不当作“可以再建一个”。读取者的角色须与 ownerUid 一致，并确认 ownerUid 对应的槽属于该家庭且 role=owner。不能由回执或 token 缓存的角色跳过当前权限校验。

提供内部 `requireFamily` 与 `guardMutation(tx, ctx)`：后者在事务中重新读取当前成员、家庭及 generation，检查权限后递增成员 mutationSeq，作为后续移除与业务写共用的冲突记录。创建分支没有成员时直接插入唯一槽；本票不实现后续票的变更入口。

错误在云端和客户端映射中同步补齐：`FAMILY_REQUIRED`、`ALREADY_IN_FAMILY`、`CONFLICT`、`NOT_FOUND`、`FORBIDDEN`，保留 `AUTH_REQUIRED`、`INVALID_INPUT`、`QUOTA_EXCEEDED`、`UNAVAILABLE`。已知业务错误不得全部被映射为网络故障，未知底层异常仍只返回安全错误。

## 6. 创建、重放与并发

### 6.1 输入、审核与限流

- 家庭名称 trim 后为 1～40 个 Unicode 码点，拒绝控制字符及非法类型；允许不同家庭同名。规范化后的名称才用于审核、摘要、存储和显示，不做隐式改名。
- requestId 是 16～128 位 ASCII 字母、数字、`-` 或 `_` 组成的非空随机标识；客户端创建意图时生成，并在任何网络发送前保存。不将其视作授权凭据。
- 名称属于用户生成文本。首次创建必须通过云端 `ContentPort.checkText`，优先使用官方 `uni-sec-check` 微信 V2 能力；只允许明确 pass，review/risky 拒绝，审核不可用返回 UNAVAILABLE。openid 仅从当前 UID 对应的可信云端身份记录获得，应用凭据仅在云端取得。审核在数据库事务之外，且不新增给客户端的审核入口。
- 已提交回执可在当前权限确认后重放，不因审核服务临时不可用而无法恢复原结果；新创建完成审核后重新确认身份，并在事务内再次核对回执和成员槽，避免审核等待期间的竞态。
- 内容适配器及其官方模块版本、凭据来源和真实调用能力在实施计划中锁定；如不能实测审核则标记未完成，不用生产恒通过替身。
- 持久化限流不依赖 #1 的单实例 Map。提议每 UID 创建入口 10 次/分钟、current 60 次/分钟；已有家庭还受家庭级 current 300 次/分钟限制，按服务端固定分钟桶计数。每次外部请求都消耗额度，包括回执重放；单次调用的内部事务重试不重复计数。配额在独立、短事务中提交后才执行业务，身份无效者不得制造任意 UID 桶。

### 6.2 原子写与重放规则

1. 验证身份、输入并执行持久化限流。回执摘要包含操作版本和规范化 name；范围限定为当前 UID 与 create 操作。
2. 优先读取回执。相同 requestId、相同摘要，且当前家庭和成员 generation 仍匹配时，返回原结果；相同 requestId 换内容返回 CONFLICT。其他用户不能命中这条回执。
3. 没有回执时，当前 UID 已有有效槽则返回 ALREADY_IN_FAMILY，不能为新 requestId 自动再建家庭或将旧成功结果冒充本次成功。
4. 尚无家庭时在事务外完成名称审核。随后在新的数据库事务内重做回执、成员槽判断。
5. 在同一事务内依次插入家庭、UID 成员槽、成功回执并提交；任一写失败整体回滚。家庭 ID 与 generation 由云端产生，固定于本次逻辑尝试；事务重试不执行审核、发消息等外部副作用。
6. 仅提交明确成功后返回创建成功。失败不在事务外补写家庭、成员或成功回执，也不靠异步删除实现正常并发约束。

同 requestId 并发时，一个事务成功，其他调用在确认冲突并重新读取后返回同一回执。不同 requestId 并发时，只能一个创建成功；其余返回 ALREADY_IN_FAMILY。相同 requestId 不同内容并发时，提交者决定原始摘要，另一个返回 CONFLICT。

### 6.3 事务适配与结果不确定

采用 `DatabasePort.transaction(fn)` 和 `tx.get/insert/replace/remove` 窄接口，统一封装 uniCloud 阿里云 `startTransaction/commit/rollback`。事务内只逐文档操作，创建用 insert 语义，不用 set/upsert 覆盖成员槽。适配器明确处理事务点读与普通点读 data 返回形状差异，并用契约测试验证。

仅对已核验的写冲突、唯一键竞争等可恢复错误做有限重试，提议最多 3 次总尝试加有界抖动。重试使用新事务快照；不能把所有异常当成重复成功。回滚失败只影响排障记录，不能掩盖原始失败或变成成功。

若 commit/网络中断导致结果不确定，重新读取当前 UID 与 requestId 的回执并验证其摘要和当前权限。找到有效回执可恢复成功；无法确认则返回可重试的 UNAVAILABLE，客户端保留原 requestId。不得根据“没收到成功响应”另发新请求或在事务外补偿写入。真实云端验证前不承诺目标云的错误码或冲突隔离语义已成立。

旧回执不能恢复已失效的成员授权。当前槽消失、generation 改变、家庭不可用或成员已变为不匹配角色时，返回 FAMILY_REQUIRED/CONFLICT 等安全错误，不回放旧家庭信息。本票不提供成员变更，相关场景用可信测试 seed 验证防线。

## 7. 客户端行为与状态边界

创建交互在既有家庭引导内完成，成功进入新增的 `/pages/family/home`。家庭页本票只显示云端确认的家庭名称、本人身份及已有退出登录操作，不露出尚未实现的邀请或管理按钮。名称必填；客户端提前提示长度和空白错误，云端独立复核。

页面通过 `features/family/api.ts` 与 `use-family.ts` 使用统一 AppClient。所有业务调用经过现有 `cloud.invoke` 和 SessionBoundary，不绕过 SDK 续期与退出排空保护。

- 登录后和每次页面 onShow：先确认身份，再调用 current。引导页已有家庭则进入家庭页，家庭页无家庭则返回引导。查询未完成或失败时不展示旧家庭内容；只有服务端返回 null 才显示可创建状态。
- 提交时禁用按钮；同一次未决意图复用 requestId 与规范化 name。创建成功后确认返回数据并导航；ALREADY_IN_FAMILY 则重新 current 并进入当前家庭。
- 网络结果不确定时保留原意图，提示重试；不偷偷生成新 requestId。若用户修改名称，先用原 requestId、原内容恢复旧意图的确定结果：成功则进入家庭；只有得到明确未写入的终态失败后才可建立新意图。一次 current=null 或暂时查不到回执不能证明旧请求以后不会提交，不据此放弃旧意图。确定性输入/审核拒绝可以直接修改后建立新意图。
- 未决意图按可信 UID 隔离保存于本地，发送前写入 `{requestId,name}`；冷启动重新确认身份并 current 后恢复：已有家庭直接进入，无家庭但有未决意图时使用原请求恢复，不能直接开放新的创建意图。退出登录清理家庭状态及本地意图，新账户不得读取上个账户草稿。退出中不接受新业务调用。
- 页面 onHide/onUnload 立即隐藏受保护内容并使旧页面代次失效；创建响应迟到可已在服务端提交，但不能恢复退出后的页面、跨账户导航或覆盖新代次状态。再次进入由云端查询恢复事实。
- AUTH_REQUIRED 清空受保护状态并回登录；暂时网络/审核不可用显示可重试状态，保留未决请求而不误删登录凭据。CONFLICT 明确提示请求内容冲突，不自动覆盖第一次名称。

视觉细节沿用当前简洁 uni-app 页面，本设计不要求新组件库或额外视觉原型。
