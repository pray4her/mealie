## 01. 微信登录并进入家庭引导

**What to build:** 用户通过微信登录，看见未加入家庭引导；退出或登录过期后无法访问受保护内容。独立小程序工程与测试工具随此功能建立，不改旧系统。

**Blocked by:** None (can start immediately；真实微信验收仍需要测试身份和空间)。

**Acceptance criteria**
- [x] 真机微信登录可用，不出现密码登录、手机号强制采集或注册全局管理员入口。
- [x] 伪造/过期登录被云端拒绝，退出后清空受保护页面状态。
- [x] 客户端构建、身份/页面测试和云端 TS 公共模块实测有独立记录，产物不包含密钥或云端实现。

## 02. 用户创建唯一家庭

**What to build:** 未加入家庭的用户创建家庭并成为所有者，之后进入家庭页。

**Blocked by:** 01 — 微信登录并进入家庭引导。

**Acceptance criteria**
- [ ] 一个用户最多有一个有效家庭成员关系，家庭拥有一个有效所有者。
- [ ] 重复提交返回原结果；并发创建不会留下第二家庭或孤儿数据。
- [ ] 家庭归属由云端确定，客户端直连数据库不可绕过约束；真实事务及唯一性经过验证。

## 03. 邀请第二位成员加入家庭

**What to build:** 所有者生成、撤销一次性邀请；另一用户接受后共享同一家庭。

**Blocked by:** 02 — 用户创建唯一家庭。

**Acceptance criteria**
- [x] 邀请 24 小时到期，只可成功使用一次，数据库/日志不保存明文可用凭据。
- [x] 普通成员无邀请管理权限；已有家庭用户不能直接加入其他家庭。
- [x] 并发接受同一邀请仅一位新成员成功，重复已成功请求不会重复消费。

三项均依据 2026-11-09 用户指定的全部验收已完成前提勾选；本轮未重跑云端/真机验收，原始证据状态独立保留。

## 04. 退出、移除成员与转移所有权

**What to build:** 普通成员退出，所有者移除成员或转移所有权；旧登录态不能继续访问原家庭。

**Blocked by:** 03 — 邀请第二位成员加入家庭。

**Acceptance criteria**
- [ ] 所有者离开前必须转移所有权或解散，转移不能出现零所有者或双所有者。
- [ ] 移除/退出与业务写入竞争时，云端权限保持正确，客户端回到家庭引导。
- [ ] 重新加入同一家庭会生成新成员代次，不能复活旧授权。

## 05. 创建、浏览和共同编辑文字菜谱

**What to build:** 家庭成员通过列表浏览菜谱、创建菜谱、查看详情和共同编辑，保存未知食材数量原文。

**Blocked by:** 02 — 用户创建唯一家庭。

**Acceptance criteria**
- [ ] 标题、食材、步骤和可选份数/时间可保存、读取，未知数量不会变成 0。
- [ ] 跨家庭资源不可读写，客户端不可篡改作者或家庭，陈旧编辑不会覆盖他人更新。
- [ ] 文本边界和内容审核有效；不依赖 AI 或图片也能完成本功能演示。

## 06. 家庭内搜索、分页和个人收藏

**What to build:** 用户筛选家庭菜谱、稳定加载下一页，并维护仅自己可见的收藏关系。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 搜索与游标始终限定当前家庭，受控标题/标签搜索不宣称全文或语义搜索。
- [ ] 同名菜谱分页不丢失、不重复，查询与页大小有界。
- [ ] 收藏操作可重复提交，不暴露或代改其他成员收藏。

## 07. 私有菜谱图片上传与预览

**What to build:** 用户上传并预览受家庭授权保护的菜谱图片，原始解析素材仅发起者和后台可读。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 上传完成后验证真实类型、大小、用途、归属及内容审核，不能绑定任意文件标识。
- [ ] 私有存储经真实匿名/跨家庭/到期访问测试；不把公开永久链接当作权限保护。
- [ ] 成员被移除后迟到的上传或审核结果不能发布/绑定，未关联文件可后续清理。

## 08. 可恢复的 AI 文本导入

**What to build:** 用户粘贴文本后获取导入任务，稍后得到自动保存的可编辑菜谱，关闭页面也能恢复查询。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 只校验通过的结构化结果可保存，每个请求最多一份菜谱，不执行模型生成的数据库或权限指令。
- [ ] 任务租约、取消、成员代次、重试竞争均有唯一终态；默认最多三次尝试，失败无重复菜谱。
- [ ] 配额原子预留、尝试用量可追踪、预算/停用开关有效；不能依赖函数返回后继续工作。
- [ ] 明确提示可能等待约一分钟开始，真实供应商测试与 fixture 测试分开记录。

## 09. AI 菜谱照片与截图导入

**What to build:** 用户上传受保护的菜谱图片，通过视觉模型解析并沿用已有任务流程保存菜谱。

**Blocked by:** 07 — 私有菜谱图片上传与预览；08 — 可恢复的 AI 文本导入。

**Acceptance criteria**
- [ ] 真实视觉接口支持菜谱图片，单位/数量未知时不编造。
- [ ] 无权访问他人的原始素材，临时链接只供受控模型读取，不暴露桶密钥。
- [ ] 非菜谱图片、审核拒绝或过期素材明确失败，不伪装成功；沿用幂等和配额。

## 10. AI 公开网址导入与失败降级

**What to build:** 用户提交可读取的公开菜谱网址，失败时能改用正文或截图，不维护自建通用抓取器。

**Blocked by:** 08 — 可恢复的 AI 文本导入。

**Acceptance criteria**
- [ ] 真实服务确有指定网页读取证据；普通模型收到 URL 或自称读过网页不算成功。
- [ ] 私网、回环、元数据、危险重定向等输入被拒绝，不尝试绕过登录或付费限制。
- [ ] 可读取与不可读取来源都经过测试；不可读不产生虚构菜谱，能力不足必须报告而非悄悄后置。

## 11. 按日期、餐次和份数安排膳食

**What to build:** 家庭成员按本地日期安排早餐、午餐、晚餐或其他餐次，可在一餐安排多道菜。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 默认北京时间，跨 UTC 日期边界不改变用户选定日，非法日期/份数被拒绝。
- [ ] 保存同家庭菜谱引用、标题快照和目标份数，多条计划可共同维护。
- [ ] 修改计划不会自动改变购物清单，共享编辑冲突不会静默覆盖。

## 12. 多张共享购物清单与手动勾选

**What to build:** 家庭成员创建多张清单、手动添加/编辑条目并共同勾选，不依赖菜谱或 AI。

**Blocked by:** 02 — 用户创建唯一家庭。

**Acceptance criteria**
- [ ] 清单和条目限家庭访问，支持已知数量/单位及原文条目。
- [ ] 两人同时勾不同条目不丢结果，重复请求不会把勾选再次翻转。
- [ ] 条目编辑有版本冲突处理，真机重进后状态保持。

## 13. 菜谱按份数加购、合并与恢复

**What to build:** 用户按目标份数将菜谱食材加入清单，合并兼容单位，并能从部分失败恢复。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱；12 — 多张共享购物清单与手动勾选。

**Acceptance criteria**
- [ ] 2 份 100g 调为 3 份得到 150g，1kg 与 500g 可合并，体积不猜成质量，“适量”保留未知。
- [ ] 每次加购保留来源和数量贡献；同请求重试不重复累计，主动新请求允许再次加购。
- [ ] 部分完成有可见状态，故障恢复及并发加购不丢量；所有算术由代码完成，不调用 AI 猜测。

## 14. 将膳食计划显式加入清单

**What to build:** 用户选择日期/餐次计划和目标购物清单，一次加购多道菜并查看处理结果。

**Blocked by:** 11 — 按日期、餐次和份数安排膳食；13 — 菜谱按份数加购、合并与恢复。

**Acceptance criteria**
- [ ] 按计划中各菜的目标份数加购，重复批次与重试不会重复增加。
- [ ] 同次操作恢复使用固定来源快照，不因计划已修改而再次计算不同结果。
- [ ] 不可用来源明确提示；计划变更不会自动改动已形成购物量。

## 15. 家庭菜谱评论

**What to build:** 家庭成员阅读和发表多条纯文本评论；本人编辑删除，所有者可删除不当评论。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 分页展示作者标签，纯文本不执行 HTML，内容有边界并经过审核。
- [ ] 本人可编辑删除，所有者不能改写别人的内容；跨家庭资源拒绝。
- [ ] 编辑冲突可见，不做回复树、点赞或举报。

## 16. 1～5 星评分与可信统计

**What to build:** 用户对家庭菜谱评分、修改或撤销；详情和列表展示平均分、人数及本人评分。

**Blocked by:** 05 — 创建、浏览和共同编辑文字菜谱。

**Acceptance criteria**
- [ ] 每人每菜一份 1～5 整数星评分，拒绝 0、6 和小数；所有者不能代改他人评分。
- [ ] 并发更新仍只有一份评分；3 星与 4 星平均为 3.5，撤完后展示“暂无评分”。
- [ ] 统计来自真实评分记录，当前页批量汇总，退出和注销的统计口径符合设计。

## 17. 菜谱删除与可恢复关联清理

**What to build:** 作者或所有者删除菜谱，立即停止访问，再恢复式清理互动/收藏/文件，保留已安排和已购物快照。

**Blocked by:** 06 — 搜索与收藏；07 — 私有图片；08 — AI 文本导入；11 — 膳食计划；13 — 菜谱加购；15 — 评论；16 — 评分。

**Acceptance criteria**
- [ ] 普通非作者成员不能删除，标记删除后不可再读取或新增关联。
- [ ] 清理中断可重试，不误删其他家庭/仍有合法引用的文件，旧任务不重建已删除结果。
- [ ] 计划保留标题并标记来源不可用，购物保留贡献快照，不静默修改已形成数量。

## 18. 账户注销、家庭解散与后台清理

**What to build:** 用户可注销，所有者可解散家庭；后台从故障恢复清理，并清除到期导入原文及孤立素材。

**Blocked by:** 04 — 成员生命周期；17 — 菜谱删除与关联清理。

**Acceptance criteria**
- [ ] 所有者先转移或解散才能注销，权限先撤销，注销后不能继续普通业务访问。
- [ ] 离家保留共享历史、清理个人收藏；注销删除个人评论评分等并匿名化共享内容；解散删除目标家庭数据。
- [ ] 重试只作用于原家庭和成员代次，不误删用户新家庭；超过 7 天原始输入被清理，已验证菜谱仍保留。
- [ ] 定时入口不可被客户端冒充，清理状态查询只授权该次操作，不恢复通用登录权限。

## 19. 空环境恢复、真机验收与发布门禁

**What to build:** 从备份在新隔离空间恢复应用，家庭成员仍能使用全部首版功能；发布前明确指出尚未满足的条件。

**Blocked by:** 09 — AI 图片导入；10 — AI 网址导入；14 — 计划加购；18 — 注销/解散与后台清理。

**Acceptance criteria**
- [ ] 数据、媒体、Schema/索引、函数/定时配置及安全配置恢复来源齐全，空环境恢复真实完成。
- [ ] 至少两个家庭多用户真机完成登录、私有图片、AI 三输入、计划加购、评论评分和撤权隔离测试。
- [ ] 域名、备案/类目、隐私、内容安全、许可、预算报警及回退条件缺失会阻止发布，不给假通过。
- [ ] 体验版/正式审核需另行人工授权，本票不自动关闭旧服务或删除旧数据。
